================================================================================
COMPANION BACKEND - EXTERNAL INTEGRATION & CONFIGURATION CHECKLIST
================================================================================

To transition this codebase from development/mock mode to a fully functional
production state, you must configure and integrate the following external
services and configurations.

--------------------------------------------------------------------------------
1. SMS / OTP GATEWAY INTEGRATION
--------------------------------------------------------------------------------
Currently: Stored in-memory (Map) and logged to the console in development.
Files to edit: `src/services/otp.service.js`

Steps required:
[ ] Select an SMS Provider (e.g., Msg91, Twilio, 2Factor, or Firebase Auth).
[ ] Install the provider's SDK (e.g., `npm install twilio` or `npm install @msg91comm/sdk`).
[ ] Add provider credentials to `.env` (API Keys, Sender IDs, Template IDs).
[ ] Update `sendOTP` in `src/services/otp.service.js` to dispatch SMS via the SDK:
    - Example: 
      ```javascript
      await twilioClient.messages.create({
        body: `Your Companion OTP is ${otp}. Valid for 5 minutes.`,
        from: process.env.TWILIO_PHONE_NUMBER,
        to: `+91${phone}`
      });
      ```

--------------------------------------------------------------------------------
2. RAZORPAY / ESCROW PAYMENT INTEGRATION
--------------------------------------------------------------------------------
Currently: Orders are created, and signatures are verified using HMAC, but funds
are only marked state-wise. Actual transfer releases/refunds are mocked.
Files to edit: `src/services/payment.service.js`

Steps required:
[ ] Obtain Razorpay Live/Test API Keys (Key ID and Key Secret).
[ ] Add `RAZORPAY_KEY_ID`, `RAZORPAY_KEY_SECRET`, and `RAZORPAY_WEBHOOK_SECRET` to `.env`.
[ ] Enable Razorpay Route (Split Payments) on your Razorpay Dashboard.
[ ] Implement Companion Linked Account onboarding to collect their bank/UPI info.
[ ] Update `releaseEscrow` in `src/services/payment.service.js` to execute Route Transfers:
    - Example:
      ```javascript
      await razorpay.transfers.create({
        account: companionProfile.razorpayAccountId, // Linked account ID
        amount: booking.companionEarnings * 100, // in paisa
        currency: "INR",
        notes: { bookingId: booking._id.toString() }
      });
      ```
[ ] Update `processRefund` in `src/services/payment.service.js` to execute refunds:
    - Example:
      ```javascript
      await razorpay.payments.refund(booking.razorpayPaymentId, {
        amount: booking.totalAmount * 100
      });
      ```
[ ] Verify the Webhook signature in `src/controllers/payment.controller.js` using:
    `Razorpay.validateWebhookSignature(body, signature, secret)`

--------------------------------------------------------------------------------
3. CLOUDINARY FILE STORAGE
--------------------------------------------------------------------------------
Currently: Configured in `src/config/cloudinary.js` and used for profile uploads.
Files to check: `src/controllers/user.controller.js` (for KYC and profile photos)

Steps required:
[ ] Create a Cloudinary account.
[ ] Configure `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, and `CLOUDINARY_API_SECRET` in `.env`.
[ ] Update the KYC submit logic (`submitKYC` in `src/controllers/user.controller.js`) if documents
    should be uploaded directly from the server or signed uploads from the frontend client.

--------------------------------------------------------------------------------
4. GOOGLE OAUTH INTEGRATION
--------------------------------------------------------------------------------
Currently: Accepts payload parameters without verification.
Files to edit: `src/services/auth.service.js`

Steps required:
[ ] Create a project in Google Cloud Console.
[ ] Enable Google Sign-In and generate a Client ID.
[ ] Install Google Auth Library: `npm install google-auth-library`
[ ] Update `googleLogin` in `src/services/auth.service.js` to verify the ID Token sent by the client:
    - Example:
      ```javascript
      import { OAuth2Client } from 'google-auth-library';
      const client = new OAuth2Client(process.env.GOOGLE_CLIENT_ID);
      const ticket = await client.verifyIdToken({
          idToken: googleToken,
          audience: process.env.GOOGLE_CLIENT_ID,
      });
      const payload = ticket.getPayload();
      // Use payload.sub (googleId), payload.email, payload.name
      ```

--------------------------------------------------------------------------------
5. SCALABILITY: REDIS INTEGRATION
--------------------------------------------------------------------------------
Currently: Sockets presence state (`onlineUsers`) and OTP storage (`otpStore`)
live in-memory (Map). If the server restarts or scales horizontally, status and 
OTPs are lost.
Files to edit: `src/socket/index.js`, `src/services/otp.service.js`

Steps required:
[ ] Provision a Redis instance (e.g., AWS ElastiCache, Redis Labs, or Docker).
[ ] Install Redis client: `npm install redis` or `npm install ioredis`.
[ ] Install Socket.io Redis Adapter: `npm install @socket.io/redis-adapter`.
[ ] Configure Socket.io to use the Redis Adapter in `src/socket/index.js`.
[ ] Refactor `otpStore` from `new Map()` to Redis client commands (`SETEX`, `GET`, `DEL`).

--------------------------------------------------------------------------------
6. PRODUCTION ENVIRONMENT SETTINGS (.env)
--------------------------------------------------------------------------------
Ensure the following are set correctly in production:
[ ] `NODE_ENV=production`
[ ] `PORT=80` or `PORT=443` (behind HTTPS reverse proxy like Nginx or Cloudflare)
[ ] `MONGO_URI` pointing to a replica set (e.g., MongoDB Atlas) with indexes pre-built.
[ ] `JWT_ACCESS_SECRET` & `JWT_REFRESH_SECRET` generated using cryptographically secure long strings.
[ ] Set correct CORS origins in `CLIENT_URL` (avoid `*` or localhost).
